# HCFP-5090：從零設計的 GPU 原生資料驅動式 Floorplanning 系統

**全名：Heterogeneous Collective FloorPlanner for RTX 5090**  
**中文名：異質區塊集體動力 Floorplanner**  
**文件版本：v0.9 Research Architecture**  
**調研截止日：2026-08-01**

> 本文件提出的是一套 **greenfield 新方案**。核心演算法、模型表示、推論流程、投影器、fallback 與軟體架構均從零設計；不依賴既有 DGLPR、Step7ML-P、Sequence-Pair、B*-tree、既有 legalizer、既有 candidate generator 或既有 Pareto gate。傳統方法只作為文獻比較與設計證據，不是執行時依賴。

## 證據層級

本套文件刻意區分四種內容：

1. **官方規格**：以 IntelLabs/FloorSet `iccad2026contest` 的 v10 README 與 evaluator 原始碼為準。
2. **已同行審查文獻**：Nature Communications、ICCAD、DAC、TCAD、NeurIPS、ICML 等正式出版物。
3. **2025–2026 預印本／近期工作**：僅作趨勢與風險參考，文件中均明確標為 preprint。
4. **HCFP-5090 設計提案**：本文件的新架構，尚未經實驗驗證；所有性能數字均是工程目標，不是已達成結果。

## 一句話技術定位

HCFP-5090 將每個不同面積、形狀與約束的 block 視為異質 agent，讓整個 block population 在 GPU 上透過 **多尺度 learned collective dynamics** 同步演化；當局部動力陷入停滯時，由 **event-triggered reconfiguration** 重建局部拓撲；最後以 **Batched Disjunctive Projection（BDP）** 選擇矩形非重疊析取方向並平行求解稀疏凸投影，得到可由 exact verifier 接受的 floorplan。

# 00　執行摘要與技術決策

## 0.1 問題判斷

FloorSet Challenge 不是單純「預測接近 ground truth 的座標」。它同時包含：

- 連續座標與連續 aspect ratio；
- 矩形兩兩非重疊的析取約束；
- fixed-shape 與 preplaced 的不可變 hard constraints；
- grouping、MIB、boundary 三類相互耦合的 soft constraints；
- block-to-block、pin-to-block HPWL 與 bounding-box area；
- 21–120 blocks 的可變規模，以及對大案例偏重的 `exp(n/12)` 總分權重。[R01][R02]

因此，單一 one-shot network 很難同時提供高品質與 100% feasibility；純 local potential field 又容易陷入局部極小；純離散 floorplan representation 難以充分利用 5090 的 dense tensor throughput；只用 gradient descent 則無法直接解決矩形非重疊的四向析取。

## 0.2 推薦方案

HCFP-5090 採五層架構：

1. **SCENE**：constraint-aware static scene encoder。
2. **POP-INIT**：多假設、分區容量感知的 population initializer。
3. **HiCoDy**：block／region／global 三尺度集體動力學。
4. **ETR**：事件觸發式衝突 component 重配置。
5. **BDP**：矩形非重疊方向 beam + batched convex projection。

最終輸出前，再經 GPU fast verifier 與 CPU exact verifier。若全部候選失敗，回傳 deterministic shelf fallback。

## 0.3 與 FloatForm 的關係

FloatForm 的可轉移思想是：

- 所有模組同步移動，而非逐一排程；
- 先在較寬鬆目標區域聚集，再逐步收縮；
- local controller 處理主要協調，稀疏 global planner 修正最後瑕疵；
- 連接完成後用 latch 保持已形成結構。[R04]

HCFP-5090 不照搬其人工勢場，因為 FloatForm 是同尺寸正方形模組，實體實驗只有 4/8 艘、模擬至 64 艘，且仍會因 local minima 需要 stochastic shake。[R04] 本方案改成：異質 rectangle-aware interaction、learned event selector、group contact tree、direction beam 與 hard projection。

## 0.4 Go / No-Go 判準

### Go

在不使用任何 learned model 的 `analytic collective dynamics + BDP` 原型上，若能達成：

- 100% hard-feasible；
- BDP 對 top population 的 legalization 成功率 ≥ 99%；
- 相較 deterministic shelf fallback，100-case v10 weighted cost 大幅下降；
- 120-block、K=32、T=24 的 pairwise dynamics 能在目標平台可接受時間內完成；

則繼續訓練 SCENE、POP-INIT 與 learned residual controller。

### No-Go / 降級

若 learned collective dynamics 無法穩定超過 analytic controller，仍保留新 greenfield 系統的：

```text
capacity-aware initializer
→ analytic multi-scale dynamics
→ event beam
→ BDP
→ exact verifier
```

這仍是一套獨立新方法，不依賴舊 floorplanner。

## 0.5 最小可行版本

Contest MVP 不必一次完成所有 learned modules。優先序為：

- P0：官方 evaluator parity、資料 adapter、exact verifier、shelf fallback。
- P1：GPU vectorized geometry、analytic typed dynamics、population manager。
- P2：BDP + direction heuristic/beam。
- P3：static encoder + learned initializer。
- P4：learned residual dynamics + event selector。
- P5：self-improvement、implicit differentiation、FP8/Triton tuning。

## 0.6 不可過度宣稱

本 survey 沒有發現截至 2026-08-01 已公開、且同時結合「異質 block-agent 集體動力、hierarchical density field、event-triggered topology reconfiguration、batched disjunctive projection」並直接針對 FloorSet 的正式論文。這是文獻檢索後的**推論**，不是專利新穎性保證，也不是已證實的 SOTA 結論。

# 01　官方問題定義與評分規格

## 1.1 資料與介面

官方 repository 說明：contest 使用 FloorSet-Lite，提供 1M training、100 visible validation、100 hidden test；每題 21–120 blocks。[R01][R03]

概念輸入為：

\[
\mathcal I=(N, A, E_{bb},E_{pb},P,C,T)
\]

- \(N\)：block count。
- \(A_i\)：每個 block 的 target area。
- \(E_{bb}\)：block-to-block weighted connectivity。
- \(E_{pb}\)：pin-to-block weighted connectivity。
- \(P\)：pin 座標。
- \(C_i=[fixed,preplaced,mib,cluster,boundary]\)。
- \(T_i=(x_i^T,y_i^T,w_i^T,h_i^T)\)：fixed/preplaced 的 hard target；自由 block 以無效值表示。

官方 evaluator 原始碼的 `solve()` 支援可選 `target_positions`；實作應採：

```python
def solve(block_count, area_targets, b2b_connectivity,
          p2b_connectivity, pins_pos, constraints,
          target_positions=None): ...
```

README 的簡化範例曾省略此參數，因此 adapter 必須以 evaluator source 為準，並寫 regression test。[R01][R02]

輸出是長度恰為 \(N\) 的 `(x, y, w, h)` list。

## 1.2 Hard constraints

任何 hard violation 都使單題 cost 固定為 10：

1. 任意兩 blocks 不得有正面積重疊；edge touching 合法。
2. 一般 soft block：

\[
\frac{|w_i h_i-A_i|}{A_i}\le 0.01
\]

3. fixed-shape block 的 \((w,h)\) 必須與 target 完全一致（evaluator tolerance 約 \(10^{-4}\)）。
4. preplaced block 的 \((x,y,w,h)\) 必須與 target 一致。[R01][R02]

HCFP 的硬規則：

- preplaced 在所有 dynamics step 的 position/shape mobility 都是 0；
- fixed-shape 的 shape mobility 是 0、position 可動；
- soft block 用 exact-area parameterization；
- final separation margin 使用比 evaluator overlap epsilon 更保守的數值。

## 1.3 Soft constraints

### Boundary

bitmask：1=left、2=right、4=top、8=bottom；corner 是 bit sum。判斷基準是**解本身的 bounding box**，不是固定 die outline。[R01][R02]

### Grouping

同群 blocks 的 polygon union 必須形成單一 connected component；矩形共邊即連通。官方 violation 是每群 connected-component count 減一。[R01][R02]

### MIB

同一 group 的 blocks 應具有完全相同 `(w,h)`；violation 為 distinct shape count 減一，evaluator 以小數位 round 後判斷。[R02]

## 1.4 Quality 與 cost

單題 feasible cost：

\[
C_i=\min\left[
\left(1+0.5(\max(0,g_{wl})+\max(0,g_{area}))\right)
\exp(2V_{rel})
\max(0.7,R^{0.3}),
9.999999
\right]
\]

其中：

- \(g_{wl}\)：相對 baseline 的 total weighted HPWL gap；
- \(g_{area}\)：相對 baseline 的 bbox-area gap；
- \(V_{rel}\)：boundary、grouping、MIB normalized violations；
- \(R\)：正式評測時「本 submission runtime / 該 testcase 所有 submissions 的 median runtime」。[R01][R02]

兩個重要含義：

1. 超過 baseline 不會讓 quality factor 低於 1，因此推論不應在已很可能達 baseline 後無限制花時間追求更低 raw HPWL/area。
2. soft violation 以 exponential 放大，零 soft violation 通常比小幅 raw HPWL 改善更優先。

## 1.5 總分權重

\[
Score=\frac{\sum_i C_i e^{N_i/12}}{\sum_i e^{N_i/12}}
\]

公開 README 的 bucket 權重為：116–120 約 34%、111–115 約 22%、106–110 約 15%。三者合計約 71%，故 large-case feasibility、quality 與 runtime tail 是第一級目標。[R01]

## 1.6 Runtime 風險

local evaluator 將 RuntimeFactor 固定為 1，無法重現跨 submission median。[R01] 因此本地要另報：

- per-size bucket p50/p90/p95/p99；
- model load、compile、warmup 與 solve 分開計時；
- CPU-only 與 GPU-enabled profiles；
- cold-start 與 warm-start；
- 100 cases 總牆鐘時間。

公開 README 未指定 final hardware/GPU 配置。RTX 5090 是本地目標平台，不應假設官方一定提供同樣設備。

## 1.7 Training helper 不能當 final truth

官方 differentiable helper 只涵蓋 HPWL、area、soft overlap/area proxy，未完整涵蓋 fixed、preplaced、MIB、cluster、boundary；final evaluator 才是權威。[R01] 因此：

- training loss 可用 smooth surrogate；
- checkpoint promotion 必須用 exact evaluator；
- model 不得以 proxy feasibility 取代 hard verifier。

# 02　文獻 Survey（截止 2026-08-01）

## 2.1 Survey 方法與範圍

範圍涵蓋：floorplanning representations、analytical/GPU placement、RL/offline learning、generative placement、swarm/self-reconfiguration、learned physics、differentiable constrained optimization、GPU systems。優先採官方論文頁、出版社、PMLR/NeurIPS proceedings、官方 repository 與 NVIDIA/PyTorch 文件。

近期 2025–2026 工作分成「已接受／正式出版」與「preprint」，不可把預印本結果當成已獨立重現的定論。

## 2.2 Classical packing representations

| 方法 | 核心優點 | 對本題限制 | HCFP 決策 |
|---|---|---|---|
| Sequence-Pair | 將相對 H/V 拓撲編碼為排列，可快速 packing | 標籤多義、離散搜索、constraints 需額外工程 | 只作比較 baseline，不進核心 |
| B*-tree | 非 slicing floorplan 的緊湊樹表示，局部 move 容易 | 仍是 sequential discrete search；對大 population GPU 利用不理想 | 不採用核心表示 [R05] |
| SA / packing heuristics | 容易構造 legal packing，成熟 | 高維搜索慢、constraints penalty 容易陷入次佳 | 用於 teacher/benchmark 也不作 runtime 依賴 |

結論：傳統 representation 擅長 legality，但會把可高度平行的連續幾何變成離散序列。HCFP 直接在 rectangle state space 中同步演化，再由 BDP 處理離散方向。

## 2.3 Analytical 與 GPU placement

### ePlace / RePlAce

ePlace 以 electrostatic analogy 將 density 看成 charge，透過 FFT 解 Poisson field，並以 Nesterov 更新；RePlAce 強化 local density smoothing 與 adaptive step size。[R06][R07]

可轉移證據：

- 長程 density pressure 應由 global field 而非純 pairwise repulsion 處理；
- 梯度式 placement 需要尺度正規化與 adaptive preconditioning；
- global continuous optimization 能快速形成有用的 topology。

限制：contest 是 21–120 個大矩形、無 fixed outline，且包含 grouping/MIB/boundary 與 exact dimensions；cell-density formulation 不能直接解完全部條件。

### DREAMPlace / AutoDMP

DREAMPlace 在 PyTorch 中用 custom wirelength/density kernels，報告相對 RePlAce 約 40× global-placement speedup而不犧牲品質；AutoDMP 再結合多目標參數搜尋。[R08][R09]

可轉移證據：

- PyTorch + custom kernels 是可行的 EDA GPU 工程路線；
- 真正 hotspot 應以 fused kernel 重寫，而非只把 Python tensor 搬到 GPU；
- GPU 最適合大量重複、固定 shape 的 wirelength/density/geometry operation。

HCFP 的差異：GPU 不只跑單一 gradient trajectory，而是同時跑 population 與 projection beams。

## 2.4 RL、offline learning 與 population search

### MaskPlace

MaskPlace 將 placement 視為高解析度 visual mask 的 sequential RL，強調 dense reward 與 zero overlap。[R10] 優點是 action mask 能直接排除明顯非法位置；缺點是逐 block 放置會累積早期決策錯誤，且每一步難以利用所有 blocks 的並行度。

### ChiPFormer

ChiPFormer 用 offline Decision Transformer 學可轉移 placement policy，並強調 fixed offline data 與 unseen circuit fine-tuning。[R11] 這支持「1M data 可學跨案例 prior」，但其 sequential token policy 不直接滿足本題同步 geometry evolution 的需求。

### WireMask-BBO / CORE

WireMask-BBO 以 wire-mask-guided evaluation 結合 BBO，並可 fine-tune 既有 placements；CORE 將 EA population diversity 與 B*-tree RL 協同，NeurIPS 2025 報告 MCNC/GSRC wirelength 改善。[R12][R13]

可轉移證據：

- population diversity 與 learned guidance 有互補性；
- 只保一條 trajectory 容易卡在局部最優；
- candidate management 應同時看 quality 與 novelty。

HCFP 不沿用 B*-tree/逐步 RL，而是把 population branching 放進 event-triggered dynamics。

## 2.5 Generative／diffusion placement

- DiffPlace（2025 preprint）以 conditional diffusion 同時生成 placements，結合 energy guidance 與 constrained manifold sampling。[R14]
- MacroDiff+（2026，arXiv 註記 accepted to IJCAI 2026）結合 heterogeneous GNN、Transformer 與 physics-guided sampling。[R15]
- MAGE（2026 preprint）使用 multimodal multi-agent refinement 與 tournament-style candidate propagation，並加入 human-like geometry metrics。[R16]

可轉移證據：

- 同時生成全部物件可避免 sequential accumulation；
- generation 必須有 explicit physical/constraint guidance；
- tournament/population refinement 能利用多候選。

不採 diffusion 主幹的理由：

- 多 step denoising 的 runtime 與 tail 較難控制；
- hard constraints 最終仍需 projection；
- 本題 N 小、pairwise geometry 可直接精確算，適合短步 dynamics；
- HCFP 希望每一步都有可解釋 residual、stagnation detector 與事件分支。

## 2.6 FloatForm 與集體自組織

FloatForm 在 Nature Communications 2026 展示 hybrid coordination：分散式 controllers 同時執行 gathering、collision avoidance、shape formation，中央 planner 只做一次稀疏 position assignment 與最後修正；初始 target region 刻意放大，之後逐步縮小，最終 latch 成結構。[R04]

可轉移的四項原理：

1. **Decoupled parallel coordination**：全部 agents 同步前進。
2. **Progressive contraction**：避免入口 congestion。
3. **Sparse global intervention**：局部規則處理大部分工作，global planner 解最後離散瑕疵。
4. **Latching**：已完成的局部接觸不要反覆破壞。

不可直接轉移：

- 模組同尺寸且正方形；floorplanning blocks 異質且 aspect ratio 可變。
- square-lattice alignment 不等於 rectangle non-overlap。
- random shake 無法精準處理高代價 topology conflict。
- 實體成功率與規模不足以證明 120-block floorplanning 的穩定性。

因此 HCFP 用 learned typed interactions、contact-tree latch、ETR 與 BDP 取代原始 APF/Hungarian。

## 2.7 Learned physics 與 equivariance

Graph Networks as Learnable Physics Engines 與 GNS 顯示 object/relationship-centric message passing 能學多物件 dynamics；GNS 特別指出多步 message passing 與對訓練狀態加 noise 有助長 rollout 穩定性。[R18][R19]

EGNN 提供 rotation/translation/reflection/permutation equivariance 的設計證據。[R20] 但本題 axis-aligned rectangles、pins 與 boundary side labels 破壞任意旋轉對稱，因此 HCFP 只強制：

- block permutation equivariance；
- 在無 anchors 時的 translation equivariance；
- 以 D4（90° rotation/reflection）做資料增強與可選 weight tying；
- 不使用完整連續 E(2) rotation equivariance。

Scalable Differentiable Physics 指出 contact sparsity 與 localized collision regions 可大幅降低 differentiable collision computation。[R21] HCFP 因 N≤120 可先用 dense pair matrix，BDP 再按 conflict components 稀疏化。

## 2.8 Differentiable optimization 與 projection

OptNet 證明 batched GPU QP 可嵌入網路並做 exact differentiation；differentiable convex optimization layers 提供 disciplined convex program 的 end-to-end differentiation框架；GLinSAT 則處理 batched general linear constraints。[R22][R23][R24]

對本題的關鍵推論：矩形 non-overlap 本身是四向析取，不能直接變成單一 convex set；但一旦為每對 active pair 選定 left/right/top/bottom，position legalization 就能轉成稀疏線性不等式 + convex proximal objective。HCFP 因此將問題拆成：

```text
learn / branch separation direction
→ batched convex projection
→ exact verification
```

這是 BDP 的核心。

## 2.9 2026 近期 optimization 趨勢

2026-07 preprint「Chip Floorplanning Combining Convex and Non-convex Optimization」使用 quadratic initialization、Adam-based nonconvex global optimization 與基於 H/V constraint graph 的 convex legalization。[R17] 它支持「continuous global stage + topology-conditioned convex legalization」；但其 fixed-outline 設定、constraint graph 與本 contest constraints 不同，且尚屬近期 preprint。HCFP 的 BDP 不預先固定單一全局 H/V graph，而是對衝突方向做 batched beam。

## 2.10 Survey 總結

| 文獻線 | 已知強項 | 尚未解決的缺口 | HCFP 取用方式 |
|---|---|---|---|
| packing representations | legality、compact encoding | 離散 sequential search | 只作 baseline |
| analytical/GPU | 快速全局場、成熟 kernels | 複合 constraints、析取 legality | global density field、GPU engineering |
| RL/offline | 學 prior、可轉移 | sequential error、online cost | offline scene prior、非逐 block policy |
| diffusion | 同步 generation、多樣性 | steps、hard legality | 不採主幹；保留 population 多樣性思想 |
| swarm/FloatForm | 平行協調、progressive shrink | 同質方格、local minima | collective dynamics、latch、sparse intervention |
| learned physics | object-centric rollout | 沒有 contest-specific exact constraints | HiCoDy backbone |
| differentiable optimization | batched hard projection | nonconvex disjunction | direction beam + BDP |

# 03　研究缺口與方法定位

## 3.1 核心研究問題

> 能否把 FloorSet floorplanning 改寫成「異質矩形 agents 的受約束集體動力系統」，利用 1M layouts 學習 interaction prior，並以 GPU-batched disjunctive projection 保證 hard feasibility？

這不是單純換一個 neural backbone，而是重新分配「learning」與「optimization」的責任：

- learning 負責初始拓撲、互動強度、衝突診斷、分離方向與候選排序；
- analytic geometry 提供可靠、尺度一致的 HPWL／overlap／bbox／constraint residual；
- projection 負責 hard feasibility；
- exact verifier 擁有最終否決權。

## 3.2 研究缺口

### 缺口 A：同時 placement 與 exact legality 的斷層

生成式方法能產生 global geometry，但 exact rectangle non-overlap、fixed/preplaced immutability 仍需額外處理。傳統 legalizer 多在模型外部，模型不知道哪些 proposal 修復代價高。

**HCFP 回應**：BDP 的 direction outcome、projection movement、feasibility 與 exact cost 都回灌訓練；projection 不是附加程式，而是一級 model interface。

### 缺口 B：local interaction 與 global compaction 的尺度差

純 pairwise repulsion 可以去重疊，卻不會自動形成低 bbox area；純 global density field 又容易破壞 cluster contact 或 boundary latch。

**HCFP 回應**：block、region、global grid 三尺度 controller；局部 contact 使用 latch，長程用 density/region pressure。

### 缺口 C：local minima 的處理不夠結構化

APF 的 random shake 可能破壞已形成的好結構；一般 gradient descent 只能在同一 topology basin 內移動。

**HCFP 回應**：ETR 將 stagnation 映射為明確事件，並在 population 中保留 branching trajectories，而不是全局亂擾動。

### 缺口 D：GPU placers多加速單一 trajectory

DREAMPlace 類方法證明 GPU kernel 可顯著加速 placement，但本題只有最多 120 blocks，單一 trajectory 不一定能完全吃滿 5090。

**HCFP 回應**：把 batch 維度用在 candidate population、event branch 與 projection beam；`[K,N,N,*]` 成為主要運算形狀。

## 3.3 方法邊界

HCFP 不聲稱：

- learned dynamics 本身可以數學保證收斂到 global optimum；
- BDP 的有限 direction beam 一定包含最佳 topology；
- 1M synthetic data 一定覆蓋 hidden test 所有 distribution shift；
- RTX 5090 本地速度等於官方 runtime；
- 文獻 survey 能建立專利法律上的新穎性。

HCFP 可被實驗驗證的主張應是：

1. 同步 population dynamics 比 sequential block policy 更適合此規模與 GPU。
2. event branching 能降低 stagnation 與 projection displacement。
3. learned direction selector + BDP 比固定 minimum-displacement direction 提高 feasible/QoR。
4. contact latching 能降低 grouping repair 反覆震盪。
5. training with projection outcomes 能提高 post-projection，而不只是 raw proposal 品質。

## 3.4 方法名稱與模組

- **HCFP-5090**：整體系統。
- **SCENE**：Static Constraint-Encoded Netlist Embedding。
- **POP-INIT**：Capacity-aware Population Initializer。
- **HiCoDy**：Hierarchical Collective Dynamics。
- **CAL**：Constraint-Aware Latching。
- **ETR**：Event-Triggered Reconfiguration。
- **BDP**：Batched Disjunctive Projection。
- **PVR**：Population Value and Risk Ranker。

## 3.5 論文式 novelty hypothesis

最可能成立的 novelty 組合不是某個單一 MLP，而是：

> 一個為 constraint-rich floorplanning 設計的 population-level learned dynamical system，使用 typed rectangle interactions、hierarchical density fields、hysteretic contact latching 與 event-triggered topology branching，並以 direction-conditioned batched projection將矩形非重疊析取轉為可 GPU 平行解的 convex subproblems。

是否能構成正式論文貢獻，必須由消融、跨 seed、large-case 與 runtime 證據支持。

# 04　HCFP-5090 完整系統架構

## 4.1 端到端資料流

```text
Official tensors
  │
  ├─ sanitize / unpad / normalize / hard-mask construction
  ▼
SCENE static encoder
  │ h_block, h_group, h_mib, h_global, quality targets
  ▼
POP-INIT: K population states
  │ centers, log-aspect, velocity, region membership, latent state
  ▼
HiCoDy unrolled collective dynamics (T steps)
  ├─ block pair field
  ├─ cluster contact/latch field
  ├─ region interaction field
  ├─ global density/bbox field
  └─ exact local hard projection each step
  │
  ├─ every H steps: stagnation/conflict diagnosis
  ▼
ETR population branch / partial restart / contact rewire
  │
  ▼
PVR surrogate ranking and risk filtering
  │ top M
  ▼
BDP direction beam × batched convex projection
  │ feasible candidates
  ▼
GPU fast verifier → CPU exact verifier
  │
  ├─ optional fixed-topology short polish
  ▼
best feasible output
  └─ if none: deterministic shelf fallback
```

## 4.2 Candidate state

對 candidate \(k\)、block \(i\)：

\[
q_{ki}^t=[c_{x},c_{y},a,v_x,v_y,v_a,h_{latent},m_{region},l_{contact}]
\]

其中 \(a=\log(w/h)\)。soft block：

\[
w_i=\sqrt{A_i e^{a_i}},\qquad h_i=A_i/w_i
\]

這使 area 在每一步都由構造滿足。固定尺寸 block 直接使用 target `(w,h)`；preplaced center 直接由 target 設定。

## 4.3 Static / dynamic 分離

### Static tensors（每題只算一次）

- area/constraint embeddings；
- dense summed b2b weight matrix；
- per-block pin weighted centroid、total weight、covariance；
- group/MIB membership matrices；
- hard target masks/values；
- SCENE embeddings。

### Dynamic tensors（每 candidate/step 更新）

- centers、dimensions、velocities；
- pair gaps/overlap depths；
- density grid；
- region assignment；
- latch states；
- conflict graph；
- energy/residual history。

Static/dynamic 分離能避免 K 候選重算 netlist encoder。

## 4.4 Population manager

Population manager 不是單純取最低 loss：

\[
score_k=\hat C_k+\lambda_r\hat P_{fail,k}+\lambda_m\hat D_{repair,k}-\lambda_n Novelty_k
\]

保留：

- 最佳 predicted post-BDP cost；
- 最低 hard residual；
- 低 soft violation；
- 不同 occupancy/topology descriptor 的 novelty elites。

Descriptor 可包含：

- block center covariance；
- region occupancy histogram；
- pairwise relative quadrant sketch；
- cluster contact tree hash；
- outline aspect ratio。

ETR 新 branch 產生後，以 deterministic reservoir replacement 淘汰最差且最相似候選。

## 4.5 Anytime property

系統始終維護：

1. `safe_fallback`：一開始即可產生；
2. `best_fast_feasible`：任何經 GPU verifier 的 feasible candidate；
3. `best_exact_feasible`：經 CPU exact verifier 的 incumbent。

runtime budget 到時，不必等待所有 candidates 完成，直接回傳最高層級 incumbent。

## 4.6 模組責任邊界

# 05　狀態表示與網路架構

## 5.1 正規化與座標系

令：

\[
S=\sqrt{\sum_i A_i}
\]

所有位置、寬高除以 \(S\)，area 除以 \(S^2\)。原點選擇：

1. 有 preplaced：preplaced + pins 的 weighted centroid；
2. 無 preplaced、有 pins：pin weighted centroid；
3. 都沒有：零點，最後將 bbox min 平移至 0 只為 deterministic output。

這保留 pin/global frame，又減少不同 case 的尺度差。

## 5.2 Block features

每 block static feature：

```text
log(area), sqrt(area)
b2b weighted degree, degree, max/mean/top-k edge weight
pin total weight, weighted centroid dx/dy, covariance/spread
fixed mask, preplaced mask
hard target x/y/w/h + valid mask
boundary 4-bit vector
cluster membership statistics
MIB membership statistics
```

group ID 不直接查 absolute embedding；每題 ID 只是任意編號。以 membership matrix 將 block pooling 成 group token，再 cross-attention 回 block。

## 5.3 Pair features

\[
e_{ij}^{static}=[\log(1+w_{ij}),sameCluster,sameMIB,hardPairFlags]
\]

動態部分：

\[
e_{ij}^{dyn}=[\Delta x,\Delta y,g_x,g_y,o_x,o_y,d_{norm},contactState]
\]

其中：

\[
g_x=|x_i-x_j|-\frac{w_i+w_j}{2},\quad
 g_y=|y_i-y_j|-\frac{h_i+h_j}{2}
\]

兩者皆負代表重疊。

## 5.4 SCENE encoder

建議 v1：

- hidden dim 320；
- 8 個 edge-biased graph-transformer blocks；
- 8 heads；
- pre-norm、SwiGLU；
- block tokens + cluster tokens + MIB tokens + boundary tokens + global token；
- b2b weight 作 attention bias；
- pin 資訊先聚合到 block，避免 pin token 數不受控。

每層：

\[
Attention_{ij}\propto
\exp\left(
\frac{Q_iK_j^T}{\sqrt d}+b_\theta(e_{ij}^{static})
\right)
\]

輸出 heads：

- block embedding \(h_i\)；
- predicted good-envelope utilization/aspect；
- ground-truth/baseline HPWL、bbox area 的 normalized target；
- per-block mobility prior；
- group contact compatibility；
- uncertainty。

## 5.5 POP-INIT：capacity-aware multi-hypothesis initializer

### Region scaffold

每 candidate 有 \(R=8\sim12\) 個 region tokens。由 global embedding + candidate mode code 產生：

\[
(r_j^{center},r_j^{capacity},r_j^{shape})
\]

block-to-region logits：

\[
L_{ij}=MLP(h_i,r_j,z_k)
\]

用幾輪 Sinkhorn-like row/column normalization 形成 soft assignment，使 region 預估總 area 不超過 capacity。這不是固定 die partition；region 會在 dynamics 中重分配。

### 初始位置

\[
c_{ki}^{0}=\sum_j p_{kij}r_{kj}^{center}+\Delta c_\theta(h_i,r,z_k)
\]

\[
a_{ki}^{0}=a_\theta(h_i,r,z_k)
\]

preplaced/fixed 立即 local-project。

### 多樣性

- K 個 learned mode tokens；
- Sobol noise code；
- best-of-K supervised matching；
- descriptor repulsion；
- quality-conditioned modes（compact、pin-oriented、cluster-first、boundary-first）。

不允許 candidate 只靠 block index 記住位置；訓練時隨機 permutation block order。

## 5.6 Hierarchical region encoder

每隔 \(H_r\) steps 根據位置、net affinity、cluster membership 更新 soft region assignment：

\[
p_{ij}\propto\exp(-\alpha\|c_i-r_j\|^2+\beta h_i^T U r_j+\gamma affinity)
\]

region token 聚合：

- area、occupancy、velocity；
- internal/external net weight；
- overlap/constraint residual；
- cluster/MIB composition。

region-level attention 輸出整體 translation、expansion、shear tendency 與 pressure，再 broadcast 至 block。

## 5.7 Global density field

將矩形以 differentiable soft rasterizer 投影到 \(G\times G\) grid（v1 用 32×32）：

\[
D_{uv}=\sum_i s_x(i,u)s_y(i,v)
\]

其中每個 edge 用 sigmoid window 近似。Global field network 輸入：

- occupancy density；
- fixed/preplaced obstacle density；
- pin attraction density；
- cluster/boundary residual maps。

輸出二維 pressure vector field。可用：

- 小型 U-Net；或
- FFT Poisson analytic field + learned residual。

v1 推薦後者：analytic field 提供穩定長程排斥，learned residual 學 contest-specific compaction。

## 5.8 PVR ranker

對 candidate 提取：

- raw smooth HPWL/bbox；
- overlap pair/count/area/max penetration；
- hard anchor residual；
- soft constraint residual；
- direction entropy；
- conflict component statistics；
- BDP predicted iteration/residual；
- scene embedding + candidate descriptor。

輸出：

```text
P(hard feasible after BDP)
predicted exact cost components
predicted projection displacement
predicted runtime / tail risk
uncertainty
```

訓練用 listwise ranking + calibrated feasibility BCE + component regression。PVR 只能減少 BDP/exact verify 次數，不能取代 verifier。

# 06　集體動力學與事件式重配置

## 6.1 HiCoDy 更新方程

對 candidate \(k\)、block \(i\)：

\[
v_{ki}^{t+1}=\rho_{ki}^t v_{ki}^{t}
+\Delta t_t D_{ki}^t
\left(F_{ki}^{analytic}+F_{ki}^{learned}\right)
\]

\[
q_{ki}^{t+1}=\Pi_{local-hard}
\left(q_{ki}^{t}+v_{ki}^{t+1}\right)
\]

- \(\rho\in[0,1]\)：learned damping；
- \(D\)：正值 diagonal preconditioner；
- \(q=[x,y,a]\)；
- `local-hard` 精確覆寫 preplaced/fixed、重建 soft area、處理相容 MIB shape。

## 6.2 Typed analytic fields

### 6.2.1 B2B / P2B attraction

使用 smooth Manhattan：

\[
softabs_\tau(z)=\tau\log(2\cosh(z/\tau))
\]

其梯度 \(\tanh(z/\tau)\) 在零附近平滑。B2B：

\[
E_{bb}=\sum_{i<j}w_{ij}
(softabs(x_i-x_j)+softabs(y_i-y_j))
\]

P2B 對固定 pin 同理。梯度作 attraction basis，不直接當唯一更新。

### 6.2.2 Rectangle overlap field

\[
o_x=\frac{w_i+w_j}{2}-|x_i-x_j|,\quad
 o_y=\frac{h_i+h_j}{2}-|y_i-y_j|
\]

activation：

\[
a_{ij}=\sigma(o_x/\tau_o)\sigma(o_y/\tau_o)
\]

minimum-displacement axis probability：

\[
p_x=\sigma((o_y-o_x)/\tau_a)
\]

force basis：

\[
F_{ij}^{ov}=a_{ij}
[p_x\phi(o_x)sgn_\tau(\Delta x),
(1-p_x)\phi(o_y)sgn_\tau(\Delta y)]
\]

learned interaction 可改變 axis gate，但不能把 hard overlap 當成不存在。

### 6.2.3 Compactness / envelope field

預測 soft envelope \([L_t,R_t,B_t,T_t]\)，對超出者施壓，對內部保留自由度。目標 envelope 不固定，而依 feasibility event 逐步收縮。

### 6.2.4 MIB shape consensus

相容 group 共享 \(a_g\)；若 target area intervals 無交集，hard area 優先，MIB 作 soft residual。Dynamics 使用 group mean/robust median attraction，final shape projection 才決定 exact common shape。

### 6.2.5 Boundary field

以 current soft bbox/extrema 計算 required edge residual。corner block 同時有兩軸 field。不可用絕對固定 canvas 邊界。

## 6.3 Learned pair interaction

pair network 不直接輸出任意世界座標向量，而輸出 basis coefficients：

\[
\alpha_{ij}=MLP(h_i,h_j,e_{ij}^{static},e_{ij}^{dyn},t)
\]

basis 包含：

- normalized relative vector；
- x-only/y-only separation；
- analytic net gradient；
- overlap minimum-axis gradient；
- contact normal/tangent；
- global density field sample。

\[
F_{ij}^{learned}=\sum_b \alpha_{ijb}B_{ijb}
\]

如此維持 translation equivariance，且比任意 vector head 更可解釋。

## 6.4 CAL：constraint-aware latching

### Contact tree

對每個 cluster group，從 pair contact scores 建立 spanning tree；每條 edge 同時預測接觸側：L/R/T/B。ground-truth contact label 由 gold rectangles 共邊關係抽取；若 gold contact graph 有多棵可能 spanning tree，訓練採多正解/edge score 而非唯一序列。

### Abutment residual

若 i 應在 j 左側：

\[
r_{normal}=right_i-left_j
\]

並要求 y intervals 有正重疊：

\[
r_{tan}=\max(0,\epsilon-(\min(top_i,top_j)-\max(bottom_i,bottom_j)))
\]

### Hysteresis latch

連續 \(K_{on}\) steps 滿足小 residual 才 latch；連續 \(K_{off}\) steps 超過較大 threshold 才 release。`off > on` 避免接觸抖動。

Latched component 對外 force 先 aggregate 到 component，再依 mobility 分配，避免一個高權重 net 把 cluster 拉散。

## 6.5 Progressive contraction

FloatForm 的 target-shape shrinking 改成 event-controlled envelope：

\[
W_t=W_*+(W_0-W_*)(1-s_t)^p
\]

但 \(s_t\) 只在以下條件增加：

- overlap residual 低於門檻；
- cluster contact residual 不惡化；
- B2B/P2B energy 在下降；
- hard anchor residual 為 0。

若 overlap/component pressure 暴增，允許局部或全局短暫 re-expand。這比單純依 iteration 線性 shrink 更穩定。

## 6.6 Conflict graph

edge 類型：

- positive overlap；
- separation direction 高 entropy；
- cluster contact missing；
- boundary competition；
- high net tension crossing dense region；
- MIB shape incompatibility。

GPU 上用 fixed-size adjacency bitmask 或 label propagation 抽 connected components。N≤120，可先用 dense bool tensor；profiling 後再寫 Triton bitset union-find。

## 6.7 ETR 觸發條件

candidate 在最近 \(K_s\) steps：

\[
\frac{E_{t-K_s}-E_t}{\max(E_{t-K_s},\epsilon)}<\delta
\]

且任一 hard/soft residual 尚高，即觸發。額外 trigger：

- velocity norm 大但 energy 不降（oscillation）；
- direction entropy 高；
- latch 反覆 on/off；
- density grid 有封閉 pocket。

## 6.8 Event vocabulary

1. **Component evacuation**：把 conflict component 平移至低 density basin。
2. **Direction branch**：複製 candidate，對 top uncertain pairs 採不同 separation directions。
3. **Region repartition**：重設 region assignment/centers。
4. **Contact rewire**：重建 cluster spanning tree 或 contact side。
5. **Aspect pulse**：對可動 soft blocks 做受限 aspect perturbation。
6. **Partial restart**：保留 anchors/latches，重初始化一個 component。
7. **Envelope relax**：暫時放大局部/全局 envelope。
8. **Candidate restart**：僅替換 population 中最差且重複的 candidate。

訓練用 teacher outcome 或 Gumbel-softmax；正式推論採 deterministic top-k + budget cap。

## 6.9 Event teacher

對 stagnation state，離線嘗試每種 event 的少量 rollout + BDP，取得：

\[
y^*=\arg\min_e C_{postBDP}(e)
\]

event selector 不只學 imitation，也學 regret：

\[
L_{event}=CE(e^*)+\lambda \left(\hat Q(e)-Q(e)\right)^2
\]

如此比把 random shake 當唯一脫困手段更可控。

# 07　GPU 原生析取約束投影：BDP

## 7.1 為何需要析取

對任意矩形 i、j，non-overlap 等價於四者至少一個成立：

\[
R_i\le L_j\ \lor\ R_j\le L_i\ \lor\ T_i\le B_j\ \lor\ T_j\le B_i
\]

這是非凸析取。任何宣稱「單一線性投影就精確解決未選方向的 rectangle non-overlap」都不正確。

BDP 的做法：

1. 只對 overlap/near-conflict pairs 建 active set；
2. direction network 輸出 L/R/T/B logits；
3. 對多組 direction assignments 建 beam；
4. 每個 assignment 形成 convex sparse projection；
5. GPU 平行求解並 exact verify。

## 7.2 Active pair broad phase

N≤120 時可先 dense 計算全部 pair gaps。active 若：

- 正重疊；或
- x/y gap 小於 margin；或
- cluster contact pair；或
- direction network uncertainty 高且可能在 polish 時碰撞。

inactive pair 已有充分 separation，不放入 QP，避免 constraints 過多。

## 7.3 Direction selector

輸入：pair static/dynamic features、scene embedding、candidate residual。輸出：

\[
p_{ij}^{dir}=softmax(z_{ij}^{L,R,T,B})
\]

teacher label 不只用 minimum displacement；對四方向各跑局部快速 projection，評估：

- displacement；
- HPWL delta；
- bbox delta；
- cycle/infeasibility；
- soft constraints delta。

用最小 post-projection cost 方向作 teacher，並保留多個近似最佳方向。

## 7.4 Convex subproblem

固定 shapes 後，variable：

\[
z=[x_1,y_1,\dots,x_N,y_N,L,R,B,T,s_{soft}]
\]

在 sequential convex iteration \(r\) 中：

\[
\min_z \frac12\|z-z_0\|_M^2+g_{wl}^Tz+g_{box}^Tz
+\lambda_s\|s_{soft}\|_1
\]

subject to：

- 已選方向的 pair separation inequalities；
- preplaced center equality；
- bbox containment；
- boundary equality（可帶 soft slack）；
- cluster contact equality + orthogonal interval overlap（soft slack）；
- 其他線性化條件。

HPWL 與 bbox area 可在外層重算 gradient，projection 內保持 convex。hard non-overlap、preplaced 不允許 slack；boundary/grouping 是 soft，可有高代價 slack。

## 7.5 Constraint examples

### i left of j

\[
x_i+\frac{w_i}{2}+\epsilon\le x_j-\frac{w_j}{2}
\]

### bbox containment

\[
L\le x_i-\frac{w_i}{2},\quad x_i+\frac{w_i}{2}\le R
\]

### left boundary

\[
x_i-\frac{w_i}{2}=L
\]

以兩條 inequalities 表示，final snap 再消除浮點殘差。

### cluster abutment（i left j）

\[
x_i+\frac{w_i}{2}=x_j-\frac{w_j}{2}
\]

\[
y_i+\frac{h_i}{2}\ge y_j-\frac{h_j}{2}+\epsilon_c
\]

\[
y_j+\frac{h_j}{2}\ge y_i-\frac{h_i}{2}+\epsilon_c
\]

## 7.6 PDHG solver

將 constraints 寫成 \(Az\le b\)。對 indicator function 的 primal-dual hybrid gradient：

\[
y^{k+1}=\max(0,y^k+\sigma(A\bar z^k-b))
\]

若 primal objective 是 diagonal quadratic + linear term：

\[
z^{k+1}=prox_{\tau f}(z^k-\tau A^Ty^{k+1})
\]

\[
\bar z^{k+1}=z^{k+1}+\theta(z^{k+1}-z^k)
\]

固定 32–64 iterations，適合 CUDA Graph。對 equality 可用兩條 inequalities 或獨立 dual channel。

### 不顯式建 sparse matrix

每個 constraint 只涉及少數 variables，可存：

```text
kind, idx_a, idx_b, coeff_a, coeff_b, rhs, hard_mask
```

`A z` 是 gather/fused expression；`A^T y` 是 scatter-add。這是第一批值得寫 Triton 的 kernel。

## 7.7 Direction beam

- baseline assignment：argmax direction logits；
- minimum-displacement assignment；
- B−2 組用 Sobol/Gumbel 對 top-U uncertain pairs 取樣；
- 先做快速 cycle/infeasibility filter；
- B 組 PDHG 同時求解。

推薦：top candidate 用 B=8；高風險 large case 可 B=16。Population 與 beam 共同形成 batch，不能讓 Python 逐條呼叫 solver。

## 7.8 Cycle 與不可行修復

若 direction inequalities 形成 positive-width cycle，primal residual 不會收斂。處理：

1. 找 residual 最大 constraint/component；
2. 在低 confidence edge 中翻轉方向；
3. 或把部分 constraints 改到另一軸；
4. 重跑有限次；
5. 仍失敗即 discard beam，不修改 hard anchors。

## 7.9 Shape-position alternating projection

外層 2–3 cycles：

1. **Shape step**：更新 soft log-aspect、MIB consensus，精確重建 area。
2. **Position BDP**：固定 shape 解 centers。
3. **Exact residual step**：重建 active pairs、contact/boundary constraints。

這避免在單一非凸 program 同時解 shape product 與 separation。

## 7.10 MIB compatibility

同組要 identical `(w,h)`，等價於 common area 也必須相同。每個 soft block hard area interval：

\[
I_i=[0.99A_i,1.01A_i]
\]

若：

\[
I_g=\bigcap_i I_i\ne\varnothing
\]

選 common area \(A_g\in I_g\) 與 common aspect，MIB 可零 violation且 hard area 合法。若有 fixed/preplaced，required shape 必須落在所有 intervals 才能廣播。若交集為空，hard area 優先，MIB 保留 soft slack；不得為了消除 MIB violation 使 solution infeasible。

## 7.11 Exact finalization

對 BDP candidate：

1. 用 `h=A/w` 重算 soft height；
2. exact overwrite hard targets；
3. 對 selected direction graph 做微小 margin propagation；
4. boundary/contact equality final snap；
5. CPU double 檢查所有 pairs 與 evaluator semantics；
6. 只有通過才進 incumbent。

## 7.12 Deterministic shelf fallback

因 contest 無 fixed outline，可以從零構造 hard-feasible fallback：

1. exact copy preplaced；
2. fixed-shape 使用 target dimensions；
3. free soft blocks 用 square 或相容 MIB common shape；
4. 取所有 preplaced 的最大 right edge，加安全 gap；
5. 其餘 blocks 沿 x 軸依序放成一條 shelf，y 選不與 preplaced 相交的高度；
6. exact verifier；若仍與 preplaced 投影相交，將整條 shelf 再向右移。

此解可能 bbox/HPWL 很差、soft violations 高，但理論上只要官方 instance 的 hard anchors 自身合法，就能避免 cost=10。它完全獨立於任何舊 legalizer。

# 08　資料工程與訓練策略

## 8.1 資料原則

FloorSet-Lite 提供 1M training layouts 與 gold geometry/metrics。[R01][R03] 目標不是把 1M layouts 全部背起來，而是學：

- netlist/constraint → global spatial prior；
- corrupted geometry → useful collective correction；
- stagnation state → reconfiguration event；
- conflict pair → separation direction；
- raw candidate → post-BDP outcome。

官方 100 validation 不進訓練；只用 internal dev 做 frequent tuning。

## 8.2 Shard 格式

避免 1M 小檔案 random I/O。預處理成 WebDataset/TAR 或等價 sequential shards：

- 每 shard 512 或 1024 cases；
- 內含原始 tensors、normalized features、labels、metadata/version hash；
- 放本地 NVMe；
- dataloader 以 bucket queue 聚合同 N range。

建議 internal split：

- 960k train；
- 20k dev；
- 20k internal test。

以 N、constraint density、pin/net density、outline aspect、topology sketch stratify；不可只隨機切檔，避免同生成模板近鄰外洩。

## 8.3 Label extraction

從 gold rectangle 抽：

- center、w/h、log-aspect；
- bbox、utilization、aspect；
- pair relative quadrant / signed gaps；
- overlap-free contact graph；
- cluster contact edges 與可接受 spanning trees；
- MIB common shape；
- boundary exact side；
- region pseudo-label（多尺度 k-means/graph clustering，僅輔助）；
- gold HPWL、bbox metrics。

不把單一離散 packing representation 當 gold label。

## 8.4 D4 augmentation

可做 horizontal mirror、vertical mirror、180°、90°/270° rotations，但必須同步：

- block/pin/preplaced coordinates；
- fixed/preplaced dimensions；
- gold rectangles；
- boundary bitmask remap；
- contact side labels；
- vector field labels。

任意角度 rotation 不合法，因 blocks 必須 axis-aligned。

## 8.5 Corruption generator

每次 batch 在線生成 2–4 類：

- global translation/scale mismatch；
- random block shift；
- controlled overlap injection；
- aspect corruption（仍維持 area）；
- cluster split / wrong contact side；
- boundary detachment；
- MIB shape mismatch；
- dense pocket collapse；
- conflict component swap；
- preplaced obstacle interference；
- partial random restart。

corruption severity 由 curriculum 控制。GNS 類工作顯示對訓練狀態加 noise 有助降低多步 rollout error；HCFP 將此原理用於幾何動力。[R18]

## 8.6 Stage A：SCENE + POP-INIT

loss：

\[
L_{init}=\min_k d(q_k^0,q^*)
+\lambda_E E_{smooth}(q_k^0)
+\lambda_{div}L_{diversity}
+\lambda_{aux}L_{scene}
\]

`d` 對 hard anchors masked，位置以 scale-normalized Huber；多解性透過 best-of-K 與 energy loss處理，而非要求所有 modes 對同一 gold。

promotion gate：oracle@K（取 K 中 post-BDP 最佳）必須顯著優於 random/shelf initialization。

## 8.7 Stage B：one-step perturbation recovery

輸入 corrupted \(q_t\)，teacher 可由：

- gold-directed vector；
- analytic constraint descent；
- high-iteration BDP/continuous teacher；
- 多 teacher outcome 中 post-score 最佳者。

loss：

\[
L_{vec}=\|\Delta q_\theta-\Delta q_{teacher}\|_{Huber}
\]

再加下一狀態 overlap、HPWL、bbox、soft residual。此階段先學穩定局部方向。

## 8.8 Stage C：multi-step unrolled dynamics

- unroll 8 → 16 → 24 steps curriculum；
- truncated BPTT；
- scheduled sampling：逐步由 teacher state 轉 model state；
- gradient clipping；
- 每數步做 local hard projection；
- loss 對 intermediate states 也計算，避免只看終點。

\[
L_{roll}=\sum_t\gamma^{T-t}
(\lambda_oL_{ov}^t+\lambda_wL_{wl}^t+\lambda_bL_{bbox}^t+
\lambda_sL_{soft}^t+\lambda_vL_{vector}^t)
\]

## 8.9 Stage D：CAL / ETR

- CAL edge/contact side：multi-label BCE + side CE + latch stability loss。
- ETR：從 hard-negative stagnation replay，對每事件做短 rollout + BDP 產生 teacher regret。
- 訓練 selector 預測 event value，不只模仿單一 event。

## 8.10 Stage E：BDP direction / PVR

對每 conflict state：

- 產生四方向 local outcomes；
- 對 top uncertain pairs 建小 beam；
- 存 feasible、movement、quality、soft residual、iterations。

Direction loss：multi-positive CE + regret-weighted ranking。PVR loss：

\[
L_{rank}=ListMLE(\hat C,C)+BCE(\hat p_f,p_f)+Huber(\hat d,d)
\]

## 8.11 Stage F：Self-improvement / DAgger

反覆：

```text
sample training cases
→ current POP-INIT + HiCoDy + ETR
→ BDP + exact-like scorer
→ add best transitions and failure states to replay
→ retrain controller/event/direction/ranker
```

replay 分層：

- success elite；
- nearly feasible；
- hard failure；
- local-minimum；
- large-case tail；
- OOD constraint combinations。

防止只學自己錯誤：每輪保留 gold corruption teacher 與 analytic baseline mixture。

## 8.12 Stage G：collective policy optimization（選配）

action 是所有 blocks 的同步 update，不做逐 block RL。reward：

\[
r_t=E(q_t)-E(q_{t+1})-\lambda_{event}Cost(event)-\lambda_{time}\Delta t
\]

只有當 supervised/DAgger 已穩定，且 exact score ablation 顯示仍有提升空間，才加入 conservative offline/short online fine-tuning。

## 8.13 完整 loss

\[
L=\lambda_iL_{init}+\lambda_vL_{vec}+\lambda_rL_{roll}
+\lambda_cL_{contact}+\lambda_eL_{event}
+\lambda_dL_{direction}+\lambda_pL_{rank}
+\lambda_uL_{uncertainty}+\lambda_{div}L_{diversity}
\]

不要一次從零 joint-train 全部；先逐模組達 promotion gate，再做低 learning-rate joint fine-tune。

## 8.14 Score-aware sampling

總分偏重大案例，但 early training 不能完全犧牲小案例。建議：

\[
P=0.4P_{uniform}+0.6P_{capped-score}
\]

\[
P_{capped-score}(N)\propto\min(e^{(N-80)/12},8)
\]

後期將 large-case 比例提高；每個 report 必須另列 106–120 bucket。

## 8.15 單卡訓練注意

- SCENE 可大 batch；unrolled HiCoDy 用較小 K_train（8–16）與 gradient accumulation；
- activation checkpoint 只放 transformer/region network，不對 geometry kernels重算過多；
- EMA weights；
- dev exact evaluation 的頻率低於 surrogate evaluation；
- 所有預估訓練時間必須先用 1k/10k cases profile，不在設計文件中假裝已知。

# 09　RTX 5090 效能工程

## 9.1 硬體事實與設計含義

RTX 5090 為 Blackwell、32 GB GDDR7、第五代 Tensor Cores，官方列出 1792 GB/s memory bandwidth。[R25] CUDA 12.8 加入 Blackwell SM_120 compiler/library support；Transformer Engine 在 Blackwell 使用 FP8/MXFP8，安裝文件要求 Blackwell 使用 CUDA 12.8+。[R26][R27]

設計含義：

- neural linear layers 適合 BF16，成熟後試 FP8/MXFP8；
- geometry/projection 多為 memory-bound、小向量與 reduction，效能重點是 fusion、layout、launch overhead；
- 32 GB 應用於 population batch，而非盲目放大模型。

## 9.2 Precision policy

| 類型 | Precision | 理由 |
|---|---|---|
| Transformer/MLP forward | BF16 default | 穩定、Tensor Core |
| 成熟 linear layers | FP8/MXFP8 optional | 壓 memory/提升 throughput |
| coordinates/dimensions | FP32 | overlap/boundary 對誤差敏感 |
| pairwise gaps/forces | FP32 accumulate | 避免 near-touching 誤判 |
| PDHG primal/dual | FP32 | residual 穩定 |
| final hard target copy | 原始 FP32/CPU double | exact semantics |
| exact verifier | CPU double/官方型別 | 最終保險 |

禁止用 FP8 儲存 geometry、constraints residual 或 final coordinates。

## 9.3 Static buckets

建議：

```text
N bucket: 32 / 64 / 96 / 128 (mask to actual N≤120)
K inference: 32 / 48 / 64 / 64–96
T dynamics: 16–32
BDP beam: 4–16
```

每 bucket 預配置 buffers，避免 shape recompilation。CUDA Graph 要求 static shapes、stable memory addresses，且不適合 data-dependent shape；故 conflict pair/constraints 都要 padded 到 fixed maximum + mask。[R28]

## 9.4 Tensor layout

```text
centers       [K, N, 2]       float32
log_aspect    [K, N]          float32
velocity      [K, N, 3]       float32
latent        [K, N, H]       bf16
pair_delta    [K, N, N, 2]    float32
pair_gap      [K, N, N, 2]    float32
edge_static   [N, N, Fe]      bf16/float32
region_state  [K, R, Hr]      bf16
occupancy     [K, G, G]       float32
```

即使 K=64、N=120，pairwise float32 tensors 仍屬數十 MB 級，遠低於 32 GB；主要 memory 壓力來自 unrolled training activations，不是 inference geometry。

## 9.5 Kernel 實作階段

### Phase 1：純 vectorized PyTorch

- `torch.compile`；
- fused SDPA；
- 無 Python block/candidate loops；
- profiler 建立 kernel/launch/memory baseline。

### Phase 2：CUDA Graph

每 bucket warmup 後 capture：

- HiCoDy 固定 step segment；
- PVR；
- BDP 固定 iterations。

ETR 的 data-dependent choice 在 graph 外只更新 event mask/parameters；event kernels本身保持固定 shape。

### Phase 3：Triton/custom CUDA（只做 hotspot）

優先：

1. pairwise rectangle gap + overlap force fusion；
2. soft rectangle rasterization + grid reduction；
3. PDHG `Az` / `A^Ty` fused gather-scatter；
4. conflict-component bitset/label reduction；
5. candidate metric reduction。

不要一開始重寫 Transformer GEMM；交給 PyTorch/Transformer Engine。

## 9.6 禁止進 inner loop 的東西

- Shapely；
- NetworkX；
- SciPy Hungarian/QP；
- JSON/CPU serialization；
- `.item()` 造成 host sync；
- Python 每 block/每 pair/每 candidate loop；
- 每 step 呼叫 official evaluator。

## 9.7 Memory budget（工程目標）

粗估上限，須以 profiler 修正：

- model weights + EMA：0.5–1.5 GB；
- optimizer states：2–6 GB；
- unrolled activations：8–18 GB；
- geometry/population tensors：<2 GB；
- data/preprocess buffers：2–4 GB；
- reserve/fragmentation：≥4–6 GB。

若 OOM，優先降低 training K/unroll 或 checkpoint activations，不降低 geometry precision。

## 9.8 Runtime profiles

### 5090 full

- BF16 neural；
- K=64（large case 可 96）；
- T=24；
- PVR top 12；
- BDP beam=8；
- CUDA Graph；
- optional FP8 linear。

### portable

- 小模型/ONNX 或 Torch CPU；
- K=8–16；
- T=12–16；
- analytic fields 權重提高；
- BDP beam=4；
- deterministic fallback always ready。

公開規格未承諾 GPU，submission 前必須確認可用環境。

## 9.9 Profiling 指標

- GPU utilization、SM occupancy、DRAM throughput；
- kernel launch count；
- graph break/recompile count；
- H2D/D2H bytes；
- per-module wall time；
- per-bucket p50/p95；
- cold-start/model-load/compile；
- BDP residual per iteration；
- exact verifier CPU time。

# 10　推論流程與提交封裝

## 10.1 solve() state machine

```text
START
  ├─ parse/sanitize input
  ├─ construct shelf fallback
  ├─ normalize + static tensors
  ├─ SCENE encode
  ├─ POP-INIT K states
  ├─ dynamics segment 0
  ├─ diagnose / ETR
  ├─ dynamics segment 1 ...
  ├─ PVR rank
  ├─ BDP top-M × beam
  ├─ fast verify
  ├─ exact verify top candidates
  ├─ optional polish if budget remains
  └─ return best exact feasible, else fallback
```

## 10.2 預處理

- unpad `-1` edges/areas；
- 聚合同一 block pair 的多 edge weight；
- 驗證 constraints shape 與 group IDs；
- target_positions 有 hard blocks 時必須存在；
- 計算 scale/origin；
- 將 target/pins 同步 normalize；
- 建 static masks 與 group membership matrices。

## 10.3 Adaptive budget

輸入 difficulty feature：

- N；
- b2b/p2b edge density；
- fixed/preplaced ratio；
- cluster/MIB/boundary count；
- initializer uncertainty；
- early overlap/conflict statistics。

budget policy 選：K、T、event slots、PVR top-M、BDP beam。對 N≥106 提高最低 budget，但必須設 p95 tail cap。

## 10.4 Early stopping

因 baseline metrics不一定傳入 solve，SCENE quality head預測 baseline-scale target。只有同時滿足：

- exact feasible candidate 已存在；
- soft violations=0 或無進一步可修；
- PVR 預測 HPWL/area 已接近 target；
- 最近 segment 改善低於 threshold；
- budget policy 判斷額外 compute 的 expected value 低；

才 early stop。

## 10.5 Optional fixed-topology polish

BDP 已選 separation/contact directions後，可固定 constraints graph，做 4–12 步 projected objective polish：

- smooth HPWL；
- linearized bbox area；
- projection回原 polytope；
- 每步 fast verify。

不允許 polish 改 hard target或引入 overlap。

## 10.6 Exact verifier parity

測試必須逐項對齊官方：

- touching edge 不算 overlap；
- area 1% boundary；
- fixed/preplaced tolerance；
- boundary bitmask；
- grouping connected components；
- MIB shape round semantics；
- HPWL center definition；
- bbox area；
- `exp(n/12)` total score。

將官方 evaluator版本/commit資訊記入 model artifact metadata。

## 10.7 Submission wrapper

```python
class HCFPOptimizer:
    def __init__(self):
        self.runtime = lazy_or_eager_load_profile()

    def solve(self, block_count, area_targets, b2b_connectivity,
              p2b_connectivity, pins_pos, constraints,
              target_positions=None):
        return self.runtime.solve(...)
```

wrapper 要做到：

- 不下載網路資源；
- checkpoint 相對路徑；
- deterministic seeds；
- 例外 catch 後回 fallback；
- 輸出 Python float tuples；
- 不把 compile/warmup意外算到某一 large testcase長尾；
- 支援 GPU unavailable 時 portable profile。

## 10.8 Artifact versioning

每個 checkpoint bundle：

```text
model.pt / safetensors
config.yaml
dataset_manifest_hash
code_git_sha
official_evaluator_hash
precision_profile
validation_report.json
```

## 10.9 失敗處理

| 失敗 | 動作 |
|---|---|
| CUDA OOM | 降 K/beam，清 cache，切 portable |
| model NaN | discard candidate；若全失敗回 fallback |
| BDP residual 不收斂 | direction flip beam / discard |
| exact overlap | margin propagation / discard |
| missing target_positions for hard block | 明確記錄 API error；不可猜 target |
| timeout imminent | 立即回 best exact incumbent/fallback |

## 11.2 必要 baselines

全部從零或公開實作，不能拿舊專案當核心：

2. random population + BDP；
3. analytic collective dynamics + BDP；

## 11.3 核心 ablation matrix

| Ablation | 要回答的問題 |
|---|---|
| remove learned initializer | 1M data 是否真的改善起點 |
| K=1 vs 8/32/64/96 | population 的邊際收益 |

| BF16 vs optional FP8 | 效能與 QoR/數值風險 |

## 11.4 Evaluation protocol

- 至少 5 model/inference seeds；
- internal test 與 official validation 分開；
- 報 mean、median、bootstrap 95% CI；
- paired per-case comparison；
- 大案例 106–120 單列；
- 任一新增 cost=10 case 視為重大 regression；
- 不只報 oracle@K，必須報實際 PVR top-1/BDP output。

## 11.5 Acceptance gates

### P0 correctness

- official parity unit tests 100%；
- fallback hard feasibility 100%；
- fixed/preplaced exact replay 100%；
- deterministic repeatability。

### P1 dynamics

- analytic dynamics 相對 random init 顯著降低 overlap與 projection movement；
- 120-block K=32 無 NaN/OOM；
- p95 runtime受控。

### P2 model

- learned initializer oracle@K 超過 analytic/random；
- learned dynamics 的 post-BDP score改善，不只 raw surrogate改善；
- large-case不退步。

### P3 default promotion

- 100 validation hard feasibility 100%；
- v10 weighted score至少有實質改善且跨 seeds穩定；
- p95 runtime在預定 cap內；
- portable fallback通過封裝。

## 11.6 Generalization tests

- N 留一區間，例如 train弱化 111–120，測 large extrapolation；
- constraint density extreme；
- pin distribution shift；
- area/aspect outliers；
- preplaced obstacle maze；
- cluster/MIB overlap；
- random block permutation；
- D4 transform consistency。

| cluster latch死鎖 | topology卡住 | latch反覆或無改善 | hysteresis、contact rewire event |
| MIB不可相容 | soft violation | area interval空 | hard area優先、soft slack |
| FP precision | near-touch overlap | exact verifier偶發 fail | FP32、margin、CPU double |
| runtime tail | leaderboard被懲罰 | p95/p99上升 | hard budget、anytime incumbent |
| data I/O bottleneck | GPU低利用 | dataloader idle | tar shards、NVMe、prefetch |
| model load/compile | cold start過長 | first case outlier | eager warmup、cache、small portable |

## 13.3 Dynamics step 偽碼

```python
def collective_step(case, scene, state, t):
    dims = exact_shape_projection(case, state.log_aspect)
    pair = rectangle_pair_features(state.center, dims)

    f_net = smooth_net_force(case, state.center)
    f_overlap = rectangle_overlap_force(pair)
    f_boundary = boundary_force(case, state.center, dims)
    f_group, latch_update = contact_latch_force(case, state, dims)
    f_mib = mib_shape_force(case, state.log_aspect)
    f_grid = global_density_field(case, state.center, dims, scene)

    learned = interaction_network(
        scene.block, state.latent, pair,
        analytic_channels=[f_net, f_overlap, f_boundary,
                           f_group, f_mib, f_grid],
        time=t,
    )
    rho, precond, delta_latent = controller(learned, scene, state)
    force = gated_sum(learned, analytic_channels)
    state.velocity = rho * state.velocity + precond * force
    state.center, state.log_aspect = bounded_update(state, t)
    state = local_hard_project(case, state)
    state.latch_edge = hysteresis_update(state.latch_edge, latch_update)
    state.latent += delta_latent
    return state, compute_diagnostics(case, state)
```

def safe_shelf(case):

# 14　創新點與論文框架

## 14.1 候選論文題目

**HCFP: Heterogeneous Collective Dynamics with Batched Disjunctive Projection for Data-Driven Floorplanning**

中文：**以異質集體動力與批次析取投影實現資料驅動式受約束 Floorplanning**

## 14.2 潛在 contributions

1. **Collective floorplanning formulation**：把所有 blocks 同步視為帶 shape/constraint state 的異質 agents，而非逐 block sequence 或固定 packing code。
2. **Hierarchical typed dynamics**：融合 rectangle-aware local interactions、region coordination、global density field。
3. **Constraint-aware latching and ETR**：cluster contact hysteresis 與結構化 local-minimum escape。
4. **BDP**：learned separation direction + GPU batched convex projection，處理矩形非重疊析取。
5. **Projection-aware learning**：以 post-projection feasibility、movement、quality 訓練 initializer/controller/ranker。
6. **Population-centric RTX implementation**：用 candidate × beam 批次填滿 GPU，而不是只加速單一路徑。

## 14.3 必須證明的假設

- H1：population simultaneous dynamics 在相同 runtime 下優於 sequential placement baseline。
- H2：hierarchical/global field 對 bbox/HPWL有獨立貢獻。
- H3：CAL 對 grouping violation和反覆拆接有顯著改善。
- H4：ETR 優於 random shake與固定 restart。
- H5：learned direction selector 降低 BDP displacement/失敗率。
- H6：projection-aware training 改善 post-BDP score。
- H7：large-case 106–120 改善不是只來自更多 compute。
